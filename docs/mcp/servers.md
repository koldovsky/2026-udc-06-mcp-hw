# MCP-сервери проєкту (Task A)

**Хост(и), у якому налаштовано:** Claude Code CLI / Claude Code VS Code extension  
**Файл конфігурації:** `.mcp.json`

---

## Сервер 1 — filesystem

| | |
|---|---|
| **Навіщо** | Дати агенту контрольований доступ до тестових даних проєкту через MCP filesystem tools. |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-filesystem ./app/data` |
| **Область доступу (scope)** | `./app/data` — серверу надано доступ лише до каталогу з даними, а не до всього репозиторію або домашнього каталогу користувача. Цього достатньо для роботи з даними застосунку і це зменшує потенційний вплив filesystem tools. |
| **Секрети** | Немає |
| **Версія** | Плаваюча (`npx -y` без зафіксованої версії). Для навчального завдання залишено актуальну версію пакета; у production-конфігурації версію варто зафіксувати для відтворюваності. |

**Які tools він дав агенту:** Claude Code показав 14 tools. Практично перевірено `list_directory`.

**Перевірка, що працює:** агента попросили через filesystem MCP перелічити файли в `app/data`. Агент викликав `Filesystem [list_directory]` і повернув `[FILE] catalog.json`.

**Roots / фактичний scope:** сервер успішно підключився зі scope `./app/data`. Claude Code не показав stderr filesystem-сервера у доступному MCP UI, тому підтвердити за stderr, чи хост передав MCP Roots, не вдалося. Не припускаємо, що `roots` є security boundary; заданий серверу шлях `./app/data` використовується як явне обмеження доступу на рівні конфігурації сервера.

## Сервер 2 — memory

| | |
|---|---|
| **Навіщо** | Дати агенту persistent memory між окремими сесіями та перевірити роботу stateful MCP-сервера. |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-memory` |
| **Область доступу (scope)** | Сервер не отримує доступу до файлової системи проєкту через конфіг. Він працює зі своїм knowledge graph і зберігає створені агентом entities, observations та relations. |
| **Секрети** | Немає |
| **Версія** | Плаваюча (`npx -y` без зафіксованої версії). Для домашнього завдання це спрощує конфігурацію; для production версію варто зафіксувати. |

**Які tools він дав агенту:** Claude Code показав 9 tools. Практично перевірено `create_entities` та `open_nodes`.

**Перевірка, що працює:** в одній сесії агент через `Memory [create_entities]` створив entity `WS6 MCP Test` з observation `Memory MCP is working`. У новій сесії через `Memory [open_nodes]` агент знайшов цю entity та повернув збережене observation, що підтвердило persistence між сесіями.

## Що НЕ підключали і чому

Розглядали `git` та `fetch`, але не підключали їх, оскільки для них потрібне додаткове Python/`uv` середовище. Для Task A достатньо `filesystem` і `memory`, які запускаються через уже наявний Node.js та не потребують токенів або додаткового runtime.

## Область доступу — головне

Filesystem MCP навмисно отримав доступ лише до `./app/data`, а не до всього репозиторію, домашнього каталогу користувача або кореня файлової системи. Цього достатньо для роботи з даними застосунку та суттєво зменшує обсяг даних і файлів, до яких MCP-сервер потенційно може отримати доступ.

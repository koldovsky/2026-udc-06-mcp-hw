# MCP-сервери проєкту (Task A)

**Хост:** Claude Code
**Файл конфігурації:** `.mcp.json` (корінь репо)

---

## Сервер 1 — filesystem

| | |
|---|---|
| **Навіщо** | Читати вихідний код, `catalog.json` та артефакти в репо безпосередньо з агента без ручного copy-paste |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-filesystem@2026.7.10 .` |
| **Область доступу (scope)** | `.` (корінь репо) — лише цей репозиторій. Домашня тека (`~`) або диск (`C:/`) не потрібні: усі файли, якими оперує завдання, лежать тут. |
| **Секрети** | немає |
| **Версія** | зафіксована `2026.7.10` |

**Які tools він дав агенту:** `read_file`, `read_multiple_files`, `write_file`, `create_directory`, `list_directory`, `directory_tree`, `move_file`, `search_files`, `get_file_info`, `list_allowed_directories`

**Перевірка, що працює:** запит «прочитай app/data/catalog.json» — агент викликав `read_file` і повернув вміст файлу без ручного відкриття.

> **Спостереження в stderr:** сервер вивів  
> `Client does not support MCP Roots, using allowed directories set from server args`  
> — тобто реальний scope визначається аргументом командного рядка, а не механізмом `roots` хоста. Це означає: якщо дати `/` або `~`, сервер матиме доступ до всього, незважаючи на налаштування хоста.

## Сервер 2 — memory

| | |
|---|---|
| **Навіщо** | Зберігати проміжні нотатки агента між запитами в рамках сесії — без запису у файли репо |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-memory@2026.7.4` |
| **Область доступу (scope)** | In-memory store; нічого не зберігається на диску і не виходить за межі процесу |
| **Секрети** | немає |
| **Версія** | зафіксована `2026.7.4` |

**Які tools він дав агенту:** `create_entities`, `create_relations`, `add_observations`, `delete_entities`, `delete_observations`, `delete_relations`, `read_graph`, `open_nodes`, `search_nodes`

**Перевірка, що працює:** агент зберіг нотатку через `create_entities` і отримав її назад через `read_graph`.

## Сервер 3 — catalog (власний)

| | |
|---|---|
| **Навіщо** | Надати типізований API над каталогом товарів: пошук, перевірка залишків, список до дозамовлення, загальна вартість запасів |
| **Транспорт** | stdio |
| **Як запускається** | `node ./mcp-server/dist/server.js` (відносний шлях від кореня репо) |
| **Область доступу (scope)** | Лише `app/data/catalog.json` (через `loadCatalog()`). Жодного мережевого виходу, жодного запису |
| **Секрети** | немає |
| **Версія** | локальний код, збирається `npm run build` в `mcp-server/` |

**Які tools він дав агенту:** `search_inventory`, `low_stock`, `inventory_value`

**Перевірка, що працює:** агент викликав `low_stock` у відповідь на питання «які товари потребують дозамовлення» і повернув 9 SKU з правильними числами.

## Що НЕ підключали і чому

- **git** (`uvx mcp-server-git`): потребує `uv`/Python, а зміст — читання git-лога — покриває filesystem-сервер. Не варте витрат на встановлення.
- **fetch** (`uvx mcp-server-fetch`): тягне довільний зовнішній контент прямо в контекст агента. Ризик prompt injection через сторонні сайти без жодної переваги для цього завдання. Свідома відмова.

---

## Область доступу — головне

Filesystem-сервер обмежено кореневою текою репо, а не `~` чи `C:/`. Власний catalog-сервер має доступ лише до `catalog.json` через `loadCatalog()` і не може ні писати, ні виходити в мережу. Memory-сервер нічого не зберігає на диску.

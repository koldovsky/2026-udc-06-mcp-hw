# MCP-сервери проєкту (Task A)

**Хост(и), у якому налаштовано:** Claude Code
**Файл конфігурації:** `.mcp.json`

---

## Сервер 1 — filesystem

| | |
|---|---|
| **Навіщо** | Читати вихідний код, `catalog.json` та інші файли репо безпосередньо з агента, без ручного copy-paste |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-filesystem@2026.7.10 .` |
| **Область доступу (scope)** | `.` — корінь репозиторію, і більше нічого. Домашня тека чи диск цілком не потрібні: усе, з чим працює завдання, лежить у цій теці |
| **Секрети** | немає |
| **Версія** | зафіксована `2026.7.10` |

**Які tools він дав агенту:** `read_file`, `read_text_file`, `read_media_file`, `read_multiple_files`, `write_file`, `edit_file`, `create_directory`, `list_directory`, `list_directory_with_sizes`, `directory_tree`, `move_file`, `search_files`, `get_file_info`, `list_allowed_directories`

**Перевірка, що працює:** попросив агента прочитати `app/data/catalog.json` — він викликав `read_file` і повернув вміст файлу без ручного відкриття.

## Сервер 2 — memory

| | |
|---|---|
| **Навіщо** | Дати агенту місце тримати проміжні нотатки в межах однієї сесії, без записів у файли репо |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-memory@2026.7.4` |
| **Область доступу (scope)** | Файлів репо не бачить, але й не суто «в пам'яті» — пише свій `memory.jsonl` у теку пакета всередині npx-кешу (поза репо). Перевірив це, зробивши тестовий запис і знайшовши файл після завершення процесу |
| **Секрети** | немає |
| **Версія** | зафіксована `2026.7.4` |

**Які tools він дав агенту:** `create_entities`, `create_relations`, `add_observations`, `delete_entities`, `delete_observations`, `delete_relations`, `read_graph`, `open_nodes`, `search_nodes`

**Перевірка, що працює:** зберіг нотатку через `create_entities`, тоді витягнув її назад через `read_graph` — повернулось те, що й записував.

## Сервер 3 — catalog (власний)

| | |
|---|---|
| **Навіщо** | Типізований API над каталогом товарів: пошук, перевірка залишків, список на дозамовлення, загальна вартість запасів |
| **Транспорт** | stdio |
| **Як запускається** | `node ./mcp-server/dist/server.js` (шлях відносний від кореня репо) |
| **Область доступу (scope)** | Лише `app/data/catalog.json`, і то через `loadCatalog()` — жодного запису, жодного мережевого виклику |
| **Секрети** | немає |
| **Версія** | свій код, збирається `npm run build` у `mcp-server/` |

**Які tools він дав агенту:** `search_inventory`, `low_stock`, `inventory_value`

**Перевірка, що працює:** спитав, які товари треба дозамовити — агент викликав `low_stock` і повернув 9 SKU з правильними цифрами.

## Що НЕ підключали і чому

- **git** (`uvx mcp-server-git`): потребує `uv`/Python заради задачі — читання git-логу, яку й так закриває filesystem-сервер. Не вартувало витрат на встановлення.

## Область доступу — головне

Filesystem-сервер обмежено коренем репозиторія. Власний catalog-сервер бачить лише `catalog.json` через `loadCatalog()` і не вміє ні писати, ні лізти в мережу. Memory-сервер нічого не пише — лише у свій файл поза ним.

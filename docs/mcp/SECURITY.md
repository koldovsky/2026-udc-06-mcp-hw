| Сервер | Дані/ресурси, до яких дістає | Секрети | Може писати? | Довіра до автора |
|---|---|---|---|---|
| filesystem | ~/VSCodeProjects/2026-udc-06-mcp-hw/app/data/ | немає | ні, тому що використовують лише read-only tools | офіційний |
| memory | ~/VSCodeProjects/2026-udc-06-mcp-hw/.cursor/memory.jsonl | немає | так, але лише в memory.jsonl | офіційний |

## 2. Ризики, які я вважаю реальними для цієї конфігурації

Для кожного — що саме може статися ТУТ, а не абстрактно.

- **Prompt injection через дані.** Filesystem mcp сервер може бути використаний для виконання будь-яких команд на хості, якщо в prompt буде вказаний шлях до файлу з командою.
- **Витік секретів.** Якби використовувалися секрети, то теоретично memory mcp міг би зберейти їх та потім використати для виконання будь-яких команд на хості.
- **Зміна поведінки сервера після встановлення.** Версія серверів зафіксована, тому якщо пакет оновиться сам, то це не вплине на роботу сервера.
- **Дії з побічним ефектом.** inventory mcp сервер не має дій з побічним ефектом, тому що використовують лише read-only tools.

## 3. Що я зробив, щоб це зменшити

- Filesystem mcp сервер обмежено фолдером `app/data/`, а не домашньою текою.
- inventory mcp сервер має лише read-only tools, жодного запису, тому не може виконати будь-які дії з побічним ефектом.
- Секрети не використовуються, тому немає ризику витіку секретів.
- Версію серверів зафіксовано замість `@latest`.
- В налаштуваннях mcp в Cursor було обрано лише read only tools.

## 4. Що лишилось прийнятим ризиком

- Filesystem mcp сервер може бути використаний для виконання будь-яких команд на хості, якщо в prompt буде вказаний шлях до файлу з командою.
- Якби використовувалися секрети, немає ніякого захисту від їх витіку.
- inventory mcp сервер може виконати будь-які дії з побічним ефектом, якщо використовуються write-only tools.

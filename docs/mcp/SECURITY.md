# Threat model MCP-інтеграцій

## 1. Що до чого має доступ

| Сервер | Дані/ресурси, до яких дістає | Секрети | Може писати? | Довіра до автора |
|---|---|---|---|---|
| filesystem | `app/data` через аргумент у `.mcp.json` | немає | так, але лише всередині scoped каталогу | офіційний MCP server |
| memory | окремий memory store процесу | немає | так, у власний store | community/official package |
| catalog | `app/data/catalog.json` через `loadCatalog()` | немає | ні | свій код |

## 2. Реальні ризики цієї конфігурації

- **Prompt injection через дані.** `filesystem` читає JSON, а memory може
  повертати збережений текст. Якщо туди потрапить інструкція для агента, вона
  є даними, а не дозволом на дію; ризик полягає в тому, що модель може її
  виконати. У seeded JSON такого контенту немає.
- **Занадто широка область доступу.** filesystem бачить лише `app/data`;
  memory не бачить файлів; catalog не приймає шлях від користувача.
- **Витік секретів.** У цій конфігурації токени не потрібні. Майбутній токен
  має передаватися як `${ENV_VAR}`, а `.env` залишається gitignored.
- **Зміна поведінки після встановлення.** Публічні сервери запускаються через
  зафіксований тег `2025.8.21`; локальний catalog versioned разом із кодом.
- **Дії з побічним ефектом.** filesystem має write tools, а memory має tools,
  що змінюють його власний store. Вони не мають доступу поза своїм scope, але
  filesystem write capability лишається прийнятим ризиком. catalog tools і
  resource read-only.

## 3. Що зроблено

- filesystem scoped до `${CLAUDE_PROJECT_DIR}/app/data`, не до home або диска;
- catalog використовує лише імпортовані й протестовані функції `app`;
- catalog не має file-write, delete або network tools;
- версії filesystem і memory зафіксовані;
- секрети не потрібні, а `.env` ігнорується Git.

## 4. Прийнятий ризик

MCP host і Node-процес мають права поточного користувача, а `${CLAUDE_PROJECT_DIR}`
є координаційним scope, не OS sandbox. Для навчального synthetic репозиторію це
прийнятно; у production потрібні окремий користувач або sandbox і контроль
оновлень пакетів.
